# 開發經驗

將每次實作中可重複使用的做法記在這裡；每筆經驗需註明適用範圍，避免把原型假設當成通用結論。

## 網頁 3D 原型與 GitHub Pages

- **經驗**：需要部署到 GitHub Pages 的 3D 瀏覽器原型，採 Three.js 搭配 Vite 產生靜態 `dist/`，並在 Vite 設定相對路徑 `base: './'`，可避免 repo 網址含子路徑時 JS／資產路徑錯誤。依賴使用 npm lockfile 固定版本；Actions 建置 `dist/` 後再部署 Pages。
- **適用範圍**：單機或前端展示型 WebGL 遊戲、GitHub Pages 靜態託管。多人即時連線、帳號、狀態持久化仍需獨立後端服務，不能由 Pages 靜態主機提供。
- **本專案應用**：用於初期驗證第一人稱移動、3D 搬運和怪物行為；之後若改用 Unity/Godot 或加入多人後端，需重新評估工具鏈。
- **建置觀察**：Three.js 0.187 的原型 bundle 約 571 KB（約 145 KB gzip）；目前可以接受作為桌機原型，但要擴大場景或加模型前應檢查載入時間、拆分程式碼及壓縮資產。

## 網路迷因素材

- **經驗**：素材加入 repository 前，記錄原始頁、作者、授權名稱／版本、授權連結及修改（例如裁切、縮圖）；把署名放在遊戲內或 `CREDITS.md`。只因圖片能在網路上看見，不代表可自由再發布。
- **適用範圍**：公開遊戲 repo、網站、展示頁及可散布的遊戲素材。正式商業發行前，仍須逐項重查素材授權和人物／商標等權利。
- **本專案應用**：首個迷因素材選用 Wikimedia Commons 上標示 CC BY 2.0 的 Grumpy Cat 像素迷因圖；保留作者 Topher McCulloch、來源頁、授權連結與縮圖使用說明。

## 迭代紀律

- **經驗**：先選一個可玩場景，把移動、互動、目標和失敗／成功循環接通，再擴增角色與關卡；每階段更新 plan，將實作中可重用的教訓回寫本檔。
- **適用範圍**：早期遊戲原型與功能迭代；不取代正式 QA、效能測試或發行前的多平台測試。

## Git 遠端狀態核對

- **經驗**：不要只依賴舊的登入提示或本機分支狀態判斷推送是否完成；用 `git ls-remote --heads origin <branch>` 讀取遠端分支，再和本機 `git rev-parse <branch>` 比對提交，才能確認遠端是否已包含目前版本。工作流程檔存在也不代表 Pages 已成功部署，部署結果需另外查 Actions 執行紀錄或實際網站。
- **適用範圍**：使用 Git 遠端的專案交付、CI/CD 與部署狀態檢查；只確認 Git 物件同步，不代表建置、部署或線上功能驗收成功。
- **本專案應用**：確認 `origin/main` 與本機 `main` 同為 `0e1125e`，因此推送已完成；本機沒有 `gh` CLI，Pages workflow 執行及網站部署仍需透過 GitHub Actions／網站狀態查證。

## 可純測試的遊戲規則

- **經驗**：把撤離門檻、移動速度等不依賴畫面或 WebGL 的規則放在純函式模組，使用 Node.js 內建 `node:test` 驗證邊界條件，不必為這些規則引入額外測試框架。
- **適用範圍**：JavaScript／Node 工具鏈中的純遊戲規則；不能取代瀏覽器實際輸入、WebGL 畫面、效能或多人同步測試。
- **本專案應用**：5 項回收門檻、搬運／衝刺速度與方鬍子貓警戒範圍測試通過。

## 第一人稱角色存在感

- **經驗**：第一人稱看不到玩家全身時，可用攝影機附掛的低面數手／爪模型提供角色辨識度和動作回饋；保持在畫面下緣，避免遮擋視線與互動物件。
- **適用範圍**：第一人稱 3D 原型、角色手部不需承載完整骨架或裝備動畫的階段；正式動畫仍應改用 rig 與動畫狀態。
- **本專案應用**：新增攝影機附掛的貓掌模型，隨移動輕微擺動，作為貓咪玩家的第一人稱提示。

## 目標進度回饋

- **經驗**：當回合有明確的數值門檻時，在目前數值旁加入原生 `<progress>`，並提供 `aria-label`；回合重設時清零，目標數值更新時同步進度，讓視覺與輔助科技都能讀到回合進度。
- **適用範圍**：有固定目標值的網頁 HUD／表單流程；若進度是多階段、非線性或不確定，需另外設計對應語意，不能硬套百分比。
- **本專案應用**：回收價值達 20 元即可撤離，新增標示「撤離目標進度」的進度條；達標後原生 progress 會封頂，分數文字仍保留實際回收總額。
